■ 도구(먼저, 한 번만 — firmware SIM-001b도 이 경로를 씀): ngspice 공식 배포(ngspice.sourceforge.io/SourceForge 공식 Windows 빌드, 공개 2주 넘은 판)를 사용자 홈 아래 격리 설치(예: C:/Users/gh/tools/ngspice/<버전>/), PATH 변경 없음, 버전·URL·sha256 기록 → 경로를 hc send t18r로 먼저 알림(orch가 firmware에 전달). KiCad 10 내장 시뮬레이터를 쓸 수 있으면 그것도 차선으로 기록.
■ 시험(각각 합격 기준을 결과 전에 커밋 → 실행 → 파형 PNG + 수치 표 + 합격/불합격):
 1) TPS26600 12V 입력 보호: 기동 돌입전류(dVdT 22nF), UVLO/OVP 문턱(분압 저항 ±1% 최악), 전류 제한(ILIM — 회로도 실제 값, lead는 10k라 적었으나 회로도 기준으로 확인·차이 보고).
 2) TPS54302 5V: 출력 전압(분압 최악), 리플, 부하 과도 0→1.5A, 기동, 인덕터 포화 여유, 22µF×4 DC 바이어스 감액 반영(제조사 곡선 근거).
 3) LDO·3V3·1V8 레일(회로도에 있는 것 — RT9013 등): 드롭아웃·부하.
 4) 전원 순서 전체 기동 파형(12V→5V→각 레일).
■ 모델: 제조사 SPICE 모델(TI PSpice 등)이 ngspice에서 안 돌면 데이터시트 수치로 만든 동작(평균) 모델 + 근거(쪽·그림) 표기. 모델 출처·라이선스 기록(재배포 불가 모델은 저장소에 넣지 말고 받는 방법만).
■ 불합격은 D-003 방식 수정 제안(분기점·선택·이유·차선) → orch 판단 후 회로도 반영 → 재시뮬. 결과는 hardware/sim/ (스크립트·넷리스트·PNG·md), VD-001 HTML이 읽을 결과 JSON(항목·기준·값·판정).
■ 완료: 커밋 → hc send t18r → 셸 루트. C-014가 먼저 끝나면 바로 이어서.
