## 3. pcb 적용 (연결 표 → 그대로 적용)

- **연결 표:** `mechanical/ren002/models_spec.py`의 `LINK` — 풋프린트 → 모델 파일 12종
- **경로:** `${KIPRJMOD}/../../../mechanical/models/<파일>.step`
- **적용 스크립트:** `python -I -B mechanical/ren002/apply_models.py <보드.kicad_pcb | openhw.pretty 폴더> ...`
  - `.kicad_pcb`: 표에 있는 풋프린트마다 모델 속성이 없으면 넣는다. 있으면 풀리지 않는 경로를 바꾼다(다른 모델 줄은 그대로). offset 0 · scale 1 · rotate 0.
  - `.pretty` 폴더: openhw 라이브러리 7개 `.kicad_mod`에 같은 블록을 넣는다(라이브러리를 고치고 보드를 갱신하는 경우).
  - 시험 결과 (pcb 23fd8da 사본): 보드 19개 · 라이브러리 7개를 바꿨고, 다시 감사하면 **빠짐 0**이다.
- **pcb 저장소 파일은 이 레인에서 고치지 않았다.** 적용 여부·방법(보드 직접 / 라이브러리 + 갱신)은 pcb가 정한다.

## 4. 렌더 (`validation/runtime/vd001/render/`, 판정 `judge.py`)

| 묶음 | 만드는 것 | 내용 |
|---|---|---|
| 렌더용 사본 | `ren002/rendersrc/` = pcb 23fd8da `hardware/` + `mechanical/models` 복사 + `apply_models.py` | 렌더 전용 사본 (pcb 파일 수정 아님). 감사 빠짐 0 |
| PCB 렌더 18장 | `scripts/02_pcb_render.py` (kicad-cli `--quality high`) | 보드마다 윗면·아랫면 정사영 + 기울임(원근·바닥 그림자) + **확대 컷**(2배로 그려 2560×1440으로 자름 — 캐리어 면마다 2장, 전면 4장) |
| 메시 | `scripts/03_export_meshes.py` (Fusion M007_assembly, pcb 23fd8da) + kicad-cli `export glb` (렌더용 사본) | GLB에 이미 든 홀더·DF30·IR LED는 Fusion 메시에서 뺀다(겹침 방지) |
| 제품 정지 10장 | `scene.py --mode stills` (Cycles OptiX 256 spp, 2560×1440) | 앞 · 뒤 · 3/4 · 분해 · 단면 · 창 근접(내부 조명) · **커넥터 면**(RJ45·DC·USB-C) · **microSD** · **사용 장면**(받침대 + RJ45·DC 케이블) · **치수선**(`04_dims_overlay.py`: 폭 71.8 · 높이 71.0 · 깊이 69.9 mm) |
| 턴테이블 | `scene.py --mode blend` → `render_chunks.py --fps 25` | 최종 모델, 8 s, 1920×1080 |

- **부품 번호:** pcb 23fd8da는 `${REFERENCE}`가 모두 F.Fab·B.Fab 층에 있고 **실크에는 부품 번호가 없다**(캐리어 99 · 전면 79개 모두 Fab).
  - 실물 실크를 그대로 그리면 번호가 안 보이는 것이 맞다.
  - 확대 컷에는 Fab 위치를 노란 글자로 겹쳐 적었다(컷마다 「주석 — 실크 아님」 표기).
  - 실크에 번호를 넣을지는 pcb 판단이다.
- **재질:**
  - 외함: 흑색 PETG — 거칠기 0.62의 무광. 객체 Z(적층 방향)로 주기 0.2 mm 층 결 범프.
  - 방열판: 흑색 아노다이즈 — 금속, 거칠기 0.27의 반광.
  - 그 밖: PMMA(투과) · 녹색 마스크 · ENIG · 백색 실크.
  - 배경: 중립 회색 바닥·월드, 접지 그림자.
- **자세:** 커넥터 면(−Y)은 서 있을 때 바닥을 향한다. 그래서 커넥터·microSD 컷은 제품을 눕혀(뒷벽이 바닥) 바닥 그림자를 유지했다. 사용 장면은 뒷면 삼각대 자리(0, −4)에 받침대를 달아 세웠다.

## 5. 다시 돌리기 (pcb 최종 커밋이 오면)

M-010부터 한 명령으로 돈다(`mechanical/m010/m010.md`). 산출물은 main 체크아웃 `validation/runtime/vd001/`에 쓴다(O-100).

```
python -I -B mechanical/m010/run_case.py --pcb-carrier <커밋> --pcb-front <커밋>
```

- 순서:
  1. 보드 사본(`pcbsrc/<보드>`)에 apply_models를 적용한다.
  2. `run_all.py`로 조건 5를 판정한다.
  3. M003 외함 문서를 만든다.
  4. PCB 렌더를 만든다(`02_pcb_render.py --src pcbsrc`).
  5. 메시와 GLB를 만든다(`--user-origin 100x100mm`).
  6. Blender 스틸 10장과 치수선을 만든다.
  7. 턴테이블을 만든다.
  8. `judge.py`로 판정한다.
  9. 대표본을 `docs/renders`에 복사한다.
- Fusion 스크립트는 `mechanical/fusion_run.py`로 돌린다. `LANE` 줄이 그 스크립트의 체크아웃 경로로 바뀐다.
- pcb가 §3 연결을 적용하면 pcb 원본 감사도 0이 된다. 그때 run_all 조건 5의 「3D 모델 빠짐」도 0이 된다(6df2865 · be3125d에서 이미 0).

## 6. 분기점

| 분기점 | 고른 것 | 이유 | 차선 |
|---|---|---|---|
| 빠짐 판정 | 보드 파일 직접 감사 | kicad-cli는 모델 속성 없는 풋프린트를 경고하지 않음 (1차 누락 원인) | kicad-cli 경고만 셈 |
