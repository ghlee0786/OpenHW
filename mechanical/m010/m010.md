# M-010 최종 케이스 경로 고정 (O-102 · D-003 #49)

## 1. 경로 (한 명령)

```
python -I -B mechanical/m010/run_case.py --pcb-carrier <커밋> --pcb-front <커밋> [--docs <폴더>] [--skip-render]
```

| # | 단계 | 도구 | 산출 (main 체크아웃 `validation/runtime/vd001/`) |
|---|---|---|---|
| 1 | 보드 사본 | `git archive <커밋> hardware`를 보드마다 → `pcbsrc/<보드>/`, 여기에 `mechanical/models` 복사 | `pcbsrc/` |
| 2 | 3D 모델 연결 | `mechanical/ren002/apply_models.py` (사본에만 적용). 감사는 원본과 적용본 두 번 (`audit_models.py`) | `boards/model_audit_<보드>[_applied].json` · `models_missing.json` |
| 3 | 보드 STEP | `kicad-cli pcb export step --subst-models --user-origin 100x100mm` (보드 보조 원점 (100,100) = 코어 중심) | `boards/{carrier,front}.step` |
| 4 | M-007 조립 · 판정 J1~J6 | `mechanical/m007/run_all.py` (Fusion `M007_assembly`). 조건 5 결과 파일을 쓴다 | `m007_judge.json` · `results/cond5-mechanical.json` · `mechanical/m007/judge.md` |
| 5 | M003 외함 문서 | Fusion `m003/scripts/01`~`04`: 새 문서에 기준 적층과 보드 STEP을 가져오고, params.py와 geom.py로 외함을 만들고, 간섭을 본 뒤 STEP/STL/f3d를 내보낸다 | `case/interference.txt` · `case/M003_enclosure.f3d` · `case/step/*.step` · `case/stl/*.stl` · `case/M003_assembly_with_refs.step` |
| 6 | 렌더 | REN-002 순서: PCB 렌더 → M007 문서 활성 → 메시 → GLB(`--user-origin`) → Blender 스틸 10 → 치수선 → 턴테이블 → `judge.py` | `render/` (pcb · stills · mesh · `ren002_turntable.mp4` · `manifest.json`) |
| 7 | 대표본 | 제품 10장, PCB 윗면·아랫면 4장, MP4 → `--docs` (기본 이 체크아웃 `docs/renders/`). 파일마다 20 MB 미만인지 확인 | 커밋은 레인에서 |

- 종료 코드는 **막힌 단계 수**다. 조건 5 불합격은 막힘이 아니다. 불합격 수는 `run.md`와 결과 파일에 적는다.
- 실행 기록은 두 곳에 남는다: `validation/runtime/vd001/m010_run.json`, `mechanical/m010/run.md`.
- 케이스를 고칠 때:
  1. `mechanical/m003/params.py` 매개변수를 바꾸고 표를 갱신한다(`export_params.py`).
  2. 같은 명령을 다시 돌린다.
  3. 커밋할 외함 산출은 `fusion_run.py mechanical/m003/scripts/04_export.py`(기본 OUT = 레인 `mechanical/m003/out`)로 만든다.

## 2. 경로 고정 (Fusion 스크립트)

- Fusion 안에서는 `__file__`이 없다. 그래서 스크립트가 30c6 worktree 경로를 직접 박고 있었다.
- 이제 모든 Fusion 스크립트는 `LANE = None`(소스)과 `MAIN = None`(산출물)을 두고 `fusion_run.py`가 채운다(공개 전환 뒤 O-117: 로컬 경로를 적지 않음). 대상:
  - m003 01~06
  - m007 01~04
  - m008 01
  - ren001 01
  - ren002 01·03
  - m010 00
- `python -I -B mechanical/fusion_run.py <스크립트> [--set 이름=값]`이 `LANE` 줄을 그 스크립트가 든 체크아웃(레인 또는 main) 경로로 바꾼 사본을 fusion_cli로 돌린다.
- fusion_cli로 직접 돌리면 main 체크아웃 기준으로 동작한다.
- 일반 Python 스크립트(run_all · audit_models · 02_pcb_render · 04_dims_overlay · scene · judge)의 산출 경로는 `MAIN`(main 체크아웃)이다.
  - 이유: O-100. 레인 worktree 안의 `validation/runtime`은 accept나 cancel 때 함께 지워진다.
- pcb 커밋은 같은 저장소에서 `git -C <main> archive`로 읽는다. pcb 레인 worktree가 없어져도 된다.
- `m003/scripts/01`은 이제 `openhw/doc = M003_enclosure`를 직접 붙인다(전에는 따로 붙였다). 보드 STEP은 `vd001/boards/`에서 가져온다.

## 4. 판정 규칙 바꾼 것 (실제 3D 모델이 연결된 보드)

- 증상: pcb 6df2865 · be3125d는 3D 모델이 모두 연결돼 있다(원본 감사 빠짐 0). 처음 돌렸을 때 조건 5가 rc **34**였다.
  - 34건은 모두 같은 부품이 두 번 그려진 것이다. 하나는 우리 자리 표시나 옛 대체 블록이고, 다른 하나는 pcb가 연결한 실제 모델이다.
- 고친 것:
  1. `03_judge.py`는 보드 바디를 KiCad 모델 이름(`BOARD_PART:<모델>`)으로 부른다.
     - 간섭 결과의 보드 바디는 프록시가 아니라 sig가 다르다. 그래서 같은 부피이면서 겹친 곳 가운데를 품는 보드 바디로 찾는다.
  2. `asm_spec.SUBST_BLOCKS`: 「3D 모델 없는 부품 대체 블록」 9개는 그 보드의 모델 연결 사본 감사 빠짐이 0이면 판정에서 뺀다.
     - 대상: J5 RJ45 · J3 USB-C · L1 · 캐리어 Q3/Q4 · 전면 X1/Q3/Q5/Q7.
     - 판정과 M003 `03_check` 둘 다 같은 규칙을 쓴다.
     - `BLK_J2_DC`(XKB 실제 치수)와 `*_PLUG`/`*_CARD`(삽입 공간)는 남긴다.
  3. `asm_spec.INTENDED`에 같은 부품 쌍을 **모델 이름으로만** 넣었다.
     - BTB A/B ↔ 짝 BTB 외형, VSMA ↔ LED 자리 표시, MH1 홀더 모델 ↔ M-008 홀더 · 스페이서 · 리드 · 패드, J2 PinHeader 모델 ↔ ICR 리드 · 패드.
     - J2 PinHeader 건은 F5에서 헤더 몸체 없는 풋프린트로 바뀌면 없어진다.
     - 다른 모델과 겹치면 그대로 실패로 센다.
  - LED 자리 표시와 VSMA 모델은 겹친 부피 27.756 mm³가 LED 하나 전체다. 위치가 같으므로 J5 광선 추적이 실제 LED 위치에 대해 맞다.

## 5. 사전 1회 결과 (pcb 중간 커밋: 캐리어 6df2865 · 전면 be3125d)

```
python -I -B mechanical/m010/run_case.py --pcb-carrier 6df2865 --pcb-front be3125d --docs <스크래치>   → rc 0 (막힌 단계 0, 18단계)
```

- **조건 5 rc 0**: J1 간섭 실패 0 (의도 39), J2 최소 틈 15/15, J3 삽입 0, J4 광축 0.000, J5 97.6 %, J6 8.0/8.0, 3D 모델 빠짐 캐리어 0 · 전면 0.
  - 이전 23fd8da의 실패 4건(O-61 USB-C 플러그 ↔ 캐리어, 스페이서 ↔ R9/R10/R11)은 pcb가 바꿔서 없어졌다.
- **케이스 수정**: `params.py usb_x` −1.0 (pcb O-61 J3 이동을 따름). 외함 형상은 같다.
  - `usb_x`는 J3 블록과 플러그 블록에만 쓰인다.
  - 내보낸 `HOUSING.stl`, `FRONT_COVER.stl`, `PRINT_COUPON.stl`의 sha256이 커밋된 `mechanical/m003/out`과 같다(a4bd9a46…, 98ec5c78…, 81b0e098…).
- **M003 문서 간섭**: 생성물이 낀 것 3건. 모두 기존 의도와 같다(keep-in 2건, 하니스 통로 0.255).
- **렌더**: `judge.py` 불합격 0, 산출 29. 대표본 15개(제품 10, PCB 4, MP4)는 모두 20 MB 미만이고 가장 큰 것이 3.95 MB다.
- 걸린 것과 고친 것(같은 원인 각 1회):
  1. 턴테이블 앞에서 없는 MP4를 지우다 멈춤 → `glob`으로.
  2. `judge.py`가 옛 렌더용 사본 경로(`ren002/rendersrc`)를 봄 → `pcbsrc/<보드>`로.
  3. 판정 rc 34 → §4.
